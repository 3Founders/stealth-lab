# Results, 2026-10-27 to 2026-10-29

What was measured while making kell's cheap-model routing save money at equal quality, and what was decided from
it. Small samples are marked as such: these are directions, not the savings number. That number comes from the
full kell-vs-Opus series, which has not run yet. Everything measured before 2026-10-27 (benchmarks, the 205-task A/B,
the repo survey, series v4-v7, memory, latency) is in [results_index.md](results_index.md); this file is its section H.

## 2. Local end-to-end (a real install on this machine)

- The prompt "is_empty_namespace": gemma did it end to end for **$0.043**, against Opus's **$0.36**. Opus ran 0 turns.
- **Before the fixes, the first prompt of a session was never dispatched,** because the model was unknown. Fixed:
  the model falls back to env, then config, then the default.
- **Two bugs failed every cheap answer** in earlier local rounds:
  - a torch DLL that cannot be imported made pytest exit 2 (fixed: `--continue-on-collection-errors`);
  - the baseline excused every failure in a test file the task named (fixed: only tests the task names itself).

## 3. Why the open models underperformed (all fixed)

| Model | What was wrong | Fix |
|---|---|---|
| GLM (z.ai) | `reasoning_effort: "high"` is read as near-minimal thinking (median 74 vs 724 reasoning tokens); reasoning was dropped between tool calls | no effort setting; `thinking.clear_thinking: false`; reasoning sent back with tool results |
| gpt-oss (General Compute) | greedy sampling by default; low effort by default (156 vs 474 reasoning tokens) | temperature 1.0, top_p 1.0, effort high |
| gemma, minimax | greedy or unset sampling | temperature 1.0, top_p 0.95 (vendors' values) |
| all | stall rule e cut GLM short in 10 of 10 runs | it counts only repeats before the first change (24 repeats or 144 calls) |

## 6. Ranking a model nobody has tested (2026-10-28/29)

The goal: a model added tomorrow gets a sensible place in the ranking on day one, and a removed one changes no other
model's place.

**What works and ships:**
- **A model the server has no card for is no longer dropped.** It is looked up in OpenRouter's live catalogue
  (cached a day), and kell sends the prices from its exec.json (`app/routing/catalog.py`, `hook.mjs`
  `candidateCards`).
- **Removing a model needs nothing.** Each model's terms are its own; there is a test for it.

**LLMRouterBench** (Li et al., ACL Findings 2026: 40 models, 31 datasets, 548,059 graded answers) was imported as a
source:

| Card prior predicting held-out models (Spearman with their actual order) | |
|---|---|
| shipped bundle (no LLMRouterBench) | -0.07 |
| fit with LLMRouterBench (aggregates only, 4-fold) | **0.60** |

- **But the full rebuild with it flattened the card regression:**
  - release-date weight 0.38 → 0.08; reasoning 0.22 → 0.04; family effects near zero;
  - so untested models bunch together, and Claude Haiku 5.5 would rank above Opus 5.5.
- **Cause:** only 5 of its 31 datasets are code. Its models were released within about a year of each other. The
  closed frontier models list no size.
- **The paper** never predicts a model from its metadata. Its routers need every model run on the training queries.
  Its lessons: most of the gain is telling task types apart (maths vs code); pool curation matters as much as the
  router; routers miss the single model that gets a hard query right ("model recall").

**A LiveCodeBench probe** was built and measured: 100 problems, graded with LiveCodeBench's own grader, 37 anchor
models. Probe scores line up poorly with kell's fitted ranking:

| Fit | Anchors | Agreement |
|---|---|---|
| shipped | 5 | r = 0.55 |
| new | 37 | r = 0.21 |

Puzzles are not repository work. Kept as the future "script" category's probe.

## 7. Decisions

- **One ranking per kind of work.** The triage judge (JEV) names the request's category, and the plan ranks for it
  (`app/routing/task_categories.py`). The categories are: repo_change, script, frontend, sql, data_science, terminal,
  agent_tools, math, knowledge, reasoning, writing, code_question.
  - Live: a bug report came back as repo_change and a SQL request as sql, in about 340 ms.
- **Weighing is cost-aware, not "best model wins".** The plan is the cheapest sequence of tries that is as reliable
  as the session's own model (ladder.py). That is LLMRouterBench's CostSave point, with the session's model in place
  of the best single model. The strongest model is chosen only where nothing cheaper reaches the target.
- **Next probe:** about 15 SWE-bench Verified tasks through kell's step agent per new model, so a new model's
  results land as ordinary observations on tasks the fit already knows.
- **Install:**
  - Setup no longer stops when one agent cannot be registered (VS Code's `code --add-mcp` crashed in the test).
  - A fresh install writes exec.json with the step agent and the sampling fixes.
  - Real users still need three things: the hosted MCP URL, an npm publish, and a Railway deploy.
