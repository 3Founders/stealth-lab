# UI audit — desktop app and chat, 2026-11-08

Scope: `desktop/` (the kell app: project bar, left project sidebar, right changes panel, composer, empty state) and `routing_kell_frontend/app/chat` (the website chat, which the desktop app copies its chat CSS from). Method: read the CSS and the JSX, traced every `transition`/`animation` on the two sidebars and the panel, computed the spring durations, and checked the button classes against the canonical set in `routing_kell_frontend`. Fixes are in the working tree; nothing here is a measured result of ours.

## The headline

The sidebar animations were not inconsistent by accident. The spring generator emitted the **99.9% settle time** as the CSS duration:

| Preset | Settle time (old) | Perceptual (now) |
|---|---|---|
| `micro` | 296 ms | **160 ms** |
| `smooth` | 775 ms | **300 ms** |
| `snappy` | 700 ms | **280 ms** |
| `bouncy` | 796 ms | **360 ms** |

Those inline values override the 160/300/360 ms fallbacks written in the CSS. So the sidebars ran at 775 ms, the canvas at a hard-coded 460 ms, hovers at 296 ms, and pop-ins at 796 ms — four different speeds for one interaction family. The fix is in both `lib/chat/spring.ts` copies: the curve is still sampled over the spring's settle time, but the CSS duration is now the perceptual one.

## Motion system

One scale, used by both sidebars and the canvas:

| Token | Value | Use |
|---|---|---|
| `--dg-micro-d` | 160 ms | hover, press, colour, focus, resize-handle fade |
| `--dg-smooth-d` | 300 ms | sidebar/panel grid, slide, fade, canvas, drawer, scrim |
| `--dg-snappy-d` | 280 ms | quick entrances (available) |
| `--dg-bouncy-d` | 360 ms | pop-ins (panel-return buttons, account card) |
| reduced motion | none | every animation/transition in both files |

The sidebar and the canvas now share `--dg-smooth-d` and `--dg-smooth`; the previous 300/460 ms split is gone.

Text rendering uses the same scale: each newly revealed word (`.dg-tok`) and each new Markdown block (`.dg-md > *`) enters on the 300 ms smooth spring. Finished Markdown blocks keep their React nodes, so the effect runs once per block and the last block grows in place without re-animating.

Buttons use the same entrance: the primary/secondary buttons, icon buttons, Stop, Send, the canvas toggle, the sidebar search and the empty-state prompts all animate in on `dg-tok-in` at 300 ms. Hover and press remain on the 160 ms micro token.

The composer textareas in both apps are now `resize: vertical` with a 50vh cap (the old `resize: none` + `field-sizing: content` made the native handle unavailable). The expand button still works for a quick tall composer.

## Sidebar behaviour (now)

- **Open**: `opacity: 1`, `transform: none`, `visibility: visible`, pointer events on.
- **Closed**: `opacity: 0`, `translateX(-16px)` left / `+16px` right, `visibility: hidden` at the end of the 300 ms, pointer events off, padding and divider removed at once, shadow removed.
- The grid column, the slide, the fade, the shadow and the resize handle all use the same 300 ms.
- Left and right are exact mirrors; the right panel also has the same edge shadow as the left.
- Below 1100 px the right panel is a drawer over the chat, with a scrim; its toggle stays visible. Below 760 px the left sidebar is the same kind of drawer, and the chat takes the full width.

## Button system

The canonical recipe is `routing_kell_frontend`'s `.btn-line` / `.btn-ink` / `.dg-mini`: glass background, transparent edge, `--dg-lift`, hover `--dg-lift-hover` + `translateY(-1px)`, 160 ms.

| Surface | Class | Status |
|---|---|---|
| Primary CTA (Open folder, Allow once, Sign in) | `btn-ink` | already canonical |
| Secondary CTA (New session, Always, Don't allow) | `btn-line` | already canonical |
| Empty-state prompts | `btn-line dg-mini` | **changed** from `.dk-empty-prompt` pill |
| Header/panel icon buttons | `dk-icon` + glass rule | **changed** |
| Stop | `dk-stop` + glass rule | **changed** |
| Send | `dk-send` (composer button) | canonical |
| List rows (recents, sessions, tree, palette) | `dk-*` flat rows | intentionally not CTA-styled |
| Window controls | `dk-winbtn` | native-like, intentionally flat |

| `console/app/chat` | Perceptual spring durations and the same 300 ms sidebar open/close block (its Composer has no draft prop, so the prompt buttons are not ported there yet) |

The desktop app and the website chat now share the same motion scale and the same button recipe. The console chat is a separate, older copy; only the motion fixes were safe to port without its own button system.

## Remaining work, in priority order

1. **Per-hunk diff review.** The panel shows the diff and a whole-change Undo. Add per-file Accept/Reject only if the engine can apply a partial patch safely; otherwise keep the diff read-only and say so.
2. **Virtualize the message list.** The log maps every line; long sessions will grow the DOM and the Markdown cost.
3. **Streaming render pipeline.** Coalesce Markdown re-parses to one per frame, lazy-load heavy blocks, cache settled HTML.
4. **Waiting-reason taxonomy.** `approval`, `error`, `question`, `prompt` in the header/session list; order by attention cost.
5. **Accessible diff.** Hunk-as-block reading with next/previous change, mirroring VS Code's Accessible Diff Viewer.
6. **Command palette recents.** Suggest recent commands and context actions on open.
7. **Live region for streaming.** `aria-live="polite"` on the newest message/status, not the whole transcript.
8. **i18n/RTL.** ICU messages, mirrored panels, LTR code/diff.
