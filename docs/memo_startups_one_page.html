kell  ·  Memo for startupskell.org.in  ·  November 2026

Your agents spend frontier prices on every step. They don't need to, and the choice of tools matters as much as the choice of model.

To: founders and engineering leads building with AI agents  ·  From: Chaitanya Deshkar and Anuj Bhadbhade, kell  ·  Ask: run one real task through kell and compare
The point. kell is a single sign-in and a single bill in front of many models and tools. It picks the model and the tool for each task from what worked before, remembers the small pieces of context that made earlier runs succeed, and gives cheap models the steps they can do. You keep your own agent (Claude Code, Cursor, our app). We change what it is wired to.

1. The problem is on the invoice

Agent bills scale with usage: “The token bill comes due: inside the industry scramble to manage AI's runaway costs” (TechCrunch, 5 Jun 2026); “AI Costs More Than The People It Replaced” (Forbes, 2 Jul 2026). Startups feel it first: every step goes to the strongest model by default, and every tool is found, installed and configured by hand.

2. Why the fix is routing, not a better model

Because the tool changes the answer. In OpenRouter's independent test of hard web-research questions (Aug 2026, 25 searches per question), the same model scored 7 to 10 points apart with different search tools:

SetupCorrectCost per question
Claude Opus 5 + Perplexity search89%$0.99
Claude Opus 5 + Exa search82%$1.29
DeepSeek V4 Flash (lower cost) + Perplexity search77%$0.08

Source: OpenRouter, via our deck. One task type, one test. We cite it to show the shape of the trade-off (the cheaper pairing gave up 12 points for about a twelfth of the cost), not as our own result.

3. What kell does

  • Model + tool recommendation. A compound pick for the task, from prior runs and benchmarks, including tool discovery.
  • Memory-based routing. Saves the slices of context that made past runs pass, tries cheaper models first, escalates when the tests say so.
  • One point for payment. Sign in once, pay once, use many tools and data sources (MCP servers, APIs, connectors) without a contract each.
  • Group chat for agents. Rooms where people and agents (yours and teammates') share context instead of re-explaining it.

4. Why now

  • Models are converging and multiplying, so the edge moves to tools, data, context and one bill.
  • Cost is now a procurement decision: Microsoft ended Claude Code licences and moved developers to Copilot (Forbes, 1 Jun 2026).

5. What is real today, and what is not

  • Built: the hosted MCP server and plug-in for Claude Code and Cursor; a Windows desktop app that runs coding tasks; shared rooms; the tool search and sign-in flow; plans paid from your own wallet.
  • Not yet proven: a savings figure we would put our name to. Our own runs are mixed: some issues were solved for much less than the strongest model alone, others cost more. We publish results with their sample sizes, or not at all.
  • Data path, plainly: your prompt and repo notes reach our server; task text and files go to the model providers we route to. We are not zero-egress, and we do not yet have SOC 2 or a pen test. If that blocks you today, tell us and we will say so.

6. Risks we would name before you do

  • Provider dependence. We route across a small set of model providers; an outage or empty balance at one degrades a turn. A third provider is on our list.
  • Recommendation quality. Routing is only worth it if the pick beats a default. That is the claim we are measuring, and the reason we ask for one real task, not a demo.
