# Operations automation (`stealth-ops`)

Thin orchestration over primitives that already exist. It adds **no** queue, shard manager, migration system, telemetry
framework, budget ledger or worker: it sequences `python -m app.ingestion.admin|worker|enqueue`, `backend/scripts/migrate.py`
and the real `POST /v1/search/recommend`, and adds the two genuinely missing integrations (Neon API, R2/S3 bucket setup).
Runbook for the underlying steps: [SETUP_TO_INGESTION.md](SETUP_TO_INGESTION.md).

```
scripts/ops/stealth-ops[.cmd]   -> scripts/ops/ops.py -> scripts/ops/stealth_ops/*.py
backend/app/ingestion/          ops_metrics.py, ops_alerts.py (+ admin subcommands)   backend/db/100_ops_alert_state.sql
backend/app/services/ingest_budget.py                                                  (worker <-> existing CostGovernor ledger)
deploy/ingestion/               cloudbuild.yaml, cloudrun/job.yaml (rendered), Dockerfile.worker (boto3 + RELEASE)
deploy/ops/grafana/             stealth-ingestion.json (generated by `stealth-ops dashboards`)
.github/workflows/              ingest-worker-batch.yml (updated), ops-alerts.yml (new)
```

Run it with the backend's Python (`asyncpg` needed; `boto3` only for object storage). `stealth-ops` is used instead of
`stealth` because `backend/scripts/stealth.py` is already the read-only `.stealth/` viewer; alias it if you prefer.

## Where secrets live

Never in the repo. Generated connection strings and tokens go to `~/.stealth-ops/secrets.env` (override with
`STEALTH_OPS_HOME`; `--env staging` uses `secrets.staging.env`). Non-secret ids (Neon project ids, snapshot names, the
last promotion gate) go to `state.json` beside it. Values reach child processes through the environment or stdin, never argv,
and error output is redacted. Load order: `backend/.env` < secrets file < process environment.

## Operator flow

```bash
export NEON_API_KEY=...                       # account API key; used, never stored
stealth-ops bootstrap-prod                    # control DB, worker credential, object storage (if configured), inventory, preflight
stealth-ops provision-shards --count 10       # K001..K010: create-or-find, migrate, verify, register (idempotent)
stealth-ops setup-object-storage
stealth-ops configure-observability --otlp-endpoint https://... --otlp-headers "Authorization=Basic ..." --sentry-dsn https://...
stealth-ops configure-secrets                 # validate every target; add --apply to push (asks first)
stealth-ops deploy-workers                    # Cloud Run job (needs a passing `promote` for production)
stealth-ops doctor                            # can we safely start ingestion right now?
stealth-ops snapshot-prod --name pre-first-ingest
stealth-ops ingest packages.jsonl --runner cloudrun --workers 8
stealth-ops watch                             # (second terminal)
stealth-ops post-batch-verify
```

| Command | What it does (and which primitive does the work) |
|---|---|
| `provision-control` / `provision-shard K001` / `provision-shards --count N` | Neon project found **by name** (`stealth-control`, `stealth-k001`, ...) or created; direct (non-pooled) URL fetched; snapshot if the DB already has data and pending migrations; `migrate.py`; extension check; `admin register-shard` (verifies schema/connectivity itself); `admin verify-refs`. Already-registered shards keep their weight/status. |
| `verify-shards` | reachability/RTT/size/connections (`admin metrics`), pending migrations, extensions, `verify-refs` |
| `snapshot-prod --name N` | Neon branch (copy-on-write, no compute) of control + every shard. Idempotent. **Never restores or deletes.** Automatic before: migrating a non-empty DB, the first `ingest`, `repair projections --rebuild`. |
| `capacity [--apply]` | measures `pg_database_size` per shard; policy from `OPS_SHARD_WARN_BYTES` / `OPS_SHARD_ROLLOVER_BYTES` (unset = no action). Rollover: mark shard `full` (stops NEW placement only) and, if no other active remote shard has room, provision + register + activate the next id. K000 is never marked full; its public weight goes to 0. Objects never move; Goal hierarchy is not consulted. |
| `configure-secrets [--target gcp,github,oracle,local] [--apply]` | one manifest (`secrets_ops.MANIFEST` + one DSN per registered shard). Check = names only. Apply = `gcloud secrets`/`gh secret set` via stdin after confirmation. Oracle = names-only env template. GitHub gets one `SHARD_ENV` secret the workflows re-export masked. IAM bindings are printed, not applied. |
| `setup-object-storage` | bucket create-if-missing, public-access block where supported, abort-multipart lifecycle, put/get/delete round trip. A bucket-scoped R2 token cannot create buckets: prints `wrangler r2 bucket create ...` and stops. |
| `mint-worker-token` | workers refuse to start without a service credential; this generates signing keys if absent, registers `ingest-worker` (`ingestion:process`), mints a token (default 7 days), stores it privately. |
| `configure-observability` | writes `OBSERVABILITY_*`, `OTEL_EXPORTER_OTLP_*`, `SENTRY_DSN`, `STEALTHLAB_ENV`, `RELEASE` (git sha) and exercises the existing exporter. |
| `deploy-workers [--target cloudrun\|github\|oracle\|local]` | Cloud Run: Cloud Build + render `job.yaml` (image, budget, service token, object storage, OTel/Sentry, one secret per shard) + `gcloud run jobs replace`. |
| `deploy-api` | `railway up` (existing `backend/railway.json`). |
| `doctor` / `preflight` | ordered checks; non-zero on any ingestion blocker (below). |
| `smoke-test` | fixture ingest -> replay -> assert one goal / one procedure / one job for the key -> drain + verify projections -> `POST /v1/search/recommend` (starts the real app locally unless `STEALTH_API_URL` is set). |
| `ingest MANIFEST [--runner none\|local\|cloudrun\|github]` | preflight -> first-ingest snapshot -> idempotent `enqueue --manifest` -> start workers -> progress line every `--interval` (+ alert evaluation) -> **safety stop** on budget exceeded/ledger unavailable or `--max-permanent-failures` new failures -> post-batch verification. |
| `watch [--notify]` | queue, throughput, p95, failures, expired leases, projection lag, shard size/DOWN, fallback rate, 429s, spend vs cap. |
| `post-batch-verify` | drain, verify projections, reconcile goals + claims, drain, verify dedup + refs, job health, alerts. |
| `verify-all`, `retry failed-ingestion`, `repair projections [--rebuild]`, `repair shard K007 [--reactivate]`, `disable-shard K007 [--replace]` | compositions of `admin verify-*`, `retry`, `drain-projections`, `reindex`, `shard-status`. `disable-shard`: `readonly` if reachable else `unhealthy`; routing untouched; retrieval reports `degraded`/`unavailable_shards`; nothing deleted or migrated. |
| `promote SRC DST` | runs config, migrations, provider health, object storage, shards, projections, dedup, refs, smoke ingestion, idempotency smoke, retrieval smoke (all on SRC), read-only checks on DST, observability + budget. A pass records `{git sha, time}`; `deploy-*` for production refuse without a fresh gate for HEAD. It deploys nothing itself. |
| `alerts`, `dashboards` | evaluate thresholds now; write the Grafana JSON. |

### Preflight rows

`CONTROL DB, MIGRATIONS, SHARDS, OBJECT STORAGE, EMBEDDINGS, JEV/JUDGE (OK|DEGRADED|FAIL), PROJECTIONS, DEDUP, REFERENCES, BUDGET,
WORKER CONFIG, OBSERVABILITY (OK|WARN), SENTRY (OK|WARN), SMOKE INGESTION, RETRIEVAL (OK|DEGRADED|FAIL)`. JEV falling back to
Gemini/Gemma reports `DEGRADED` (not a blocker). Observability/Sentry only block when `OPS_OBSERVABILITY_REQUIRED=1` /
`OPS_SENTRY_REQUIRED=1`. `--skip-smoke` skips the two write-capable rows. The smoke test writes one clearly labelled **public**
goal/procedure (`stealth-ops smoke test: ...`); run `promote` against staging if you do not want it in production.

## Cost enforcement (workers now obey the API's budget)

Audit result: the API checked `CostGovernor` (`DAILY_LLM_BUDGET_USD`, `llm_spend`), but **nothing in the ingestion path
recorded or checked spend** — embeddings, identity/claim judgments, JEV and fallback models were uncapped.
Now (`ingest_budget.py`, same ledger, same cap, scope key `ingestion`):

* every judge call (`SemanticJudge._run`, per provider attempt, so fallbacks are covered) and every embedding call is checked
  before it is made and recorded after;
* worker lanes stop **leasing** when the budget is exceeded (or the ledger is unreadable — unknown spend is not "no spend");
  loop workers wait, `--once` workers exit with code **3**;
* a call that starts over budget raises `BudgetExceeded`; the worker hands the job back (`release`, attempt not spent);
* warning at `INGEST_BUDGET_WARN_FRACTION` (default 0.8): log + telemetry event + `cost.budget_near_limit` alert;
* `INGEST_BUDGET_ENFORCE=0` disables it (not recommended). Tokens are estimates (~4 chars/token), as documented for `CostGovernor`;
  JEV is priced 0 unless `INGEST_JEV_COST_PER_CALL_USD` is set.

## Observability

Already in the repo: OTel spans (`telemetry.py`), Sentry with redaction (`observability.py`). What was missing: the **worker never
called `observability.init`** (traces/Sentry were dark for ingestion) — fixed; spans are flushed on exit. Telemetry can never fail
a job (exporter is wrapped; init never raises).

Hosted destination — an account only you can create. Smallest option: **Grafana Cloud** free tier (OTLP gateway for traces, and its
PostgreSQL datasource powers the dashboard below). Create a stack, an *OTLP* access-policy token, then:
`stealth-ops configure-observability --otlp-endpoint https://otlp-gateway-<zone>.grafana.net/otlp --otlp-headers "Authorization=Basic <base64 instance:token>" --sentry-dsn <dsn> --environment production`.
Phoenix Cloud or any OTLP/HTTP backend works the same way. Then `configure-secrets --apply` distributes it.

**Dashboards** (`deploy/ops/grafana/stealth-ingestion.json`, import into Grafana with a read-only Postgres datasource on the
control DB): ingestion (queue, throughput, avg/p95 duration, failures, leases), providers (calls, judge mix/fallback, failures/429s),
retrieval (degraded, candidates, shards touched/unavailable), database (registry, projection lag, control DB size/connections),
cost (spend/hour, by provider). Span latencies come from the traces; per-shard size/connections/RTT are live probes surfaced by
`watch`/`admin metrics` and used by alerts (SQL on the control DB cannot read another shard's `pg_stat_*`).

**Alerts** (`ops_alerts.py`; thresholds `OPS_*`, see `Thresholds`): permanent ingestion failure, repeated retryable failures, expired-lease
spike, projection lag, projection outbox failure, shard unavailable, shard near/at capacity, connection saturation, embedding outage,
judge outage, semantic fallback spike, retrieval degraded, budget near/exceeded/ledger unavailable, and last-run failures of
`verify-dedup|refs|projections`. Noise control: warnings need `OPS_ALERT_FOR_CHECKS` (2) consecutive evaluations, criticals fire once,
re-notify only after `OPS_ALERT_RENOTIFY_MINUTES` (60), one `RESOLVED`. Delivery: `OPS_ALERT_WEBHOOK_URL` (Slack/Discord).
Scheduler: `.github/workflows/ops-alerts.yml` every 10 min (integrity scans hourly), or `stealth-ops watch --notify`.

## Frontend

`prod_frontend` already has opt-in Sentry (`lib/monitoring.ts`: DSN at build time, environment/release tags, DNT/GPC respected,
no replay/tracing). Not done here: source-map upload (needs a Sentry auth token in your CI) and no product analytics was added.

## What still needs a human

* Neon account/billing and `NEON_API_KEY`; plan limits decide `OPS_SHARD_*_BYTES` (autosuspend cannot be disabled on plans that
  forbid it: creation still succeeds and preflight/latency will show it).
* Creating the R2 bucket if your token cannot (`wrangler r2 bucket create`), Cloudflare/Google/GitHub logins (`gcloud auth`, `gh auth`),
  the Cloud Run job service account's Secret Manager IAM binding.
* Creating the hosted OTLP account and Sentry project; pasting endpoint/headers/DSN.
* Restoring from a snapshot or deleting anything (never automated), and approving `configure-secrets --apply`.
* Renewing the worker credential before it expires (`mint-worker-token`, then `configure-secrets --apply`).
