# kell in Claude Code: the 10-prompt test, the polish, and the re-runs (2026-10-29/30)

One repository (kell-try: jsonargparse, Windows, the hosted MCP at mcp.kell.org.in), Claude Code on a kell profile.
Prompts typed by hand on 10-29, then sent through headless `claude -p` sessions on 10-30 (a fresh session each, the
change undone after). Costs are everything a prompt cost: the cheap tries, kell's helpers (brief, locate, explain,
describe), the Sonnet reviews, and the session model (Opus) when it ran. Opus's cost is Claude Code's own
`total_cost_usd`. One run per prompt: these are observations, not averages.

## 1. The 10-prompt test (10-29, before the polish)

The judge (JEV) classified all 10 the way they should be (kind, work, category). Small models answered 4 of the 6
questions and chat turns; real, clear changes (a script, a CI workflow) were made by cheap models and applied. Nothing
wrong was applied. What was weak:

- Requests built on something that is not there (a typo that does not exist, a docstring example that does not exist)
  ran 14-15 minutes and ended with Opus: two cheap models had correctly said "it is not there", and kell counted that
  as failing.
- Every change waited 2.5-3.75 min for the baseline (the whole suite on the unchanged code), the same 417 failures each
  time. The 417 were the machine's Python 3.14, which this jsonargparse does not support: "passes the check" meant
  little.
- The side helpers (brief, explain, describe) failed on every dispatch: gemma on General Compute took 7+ s to its first
  token; describe also rejected every reply (a step-count mismatch).
- Models wrote Linux commands on Windows (an answer the review rejected; an agent looping on `echo '...'`).

## 4. Savings (estimate)

Against Opus doing the same prompt, where Opus's cost on that prompt was measured tonight (clone, slow tests, dead
code, the missing example, clean up, type hints): kell **$1.04** vs Opus **$1.50** for the six, **-31%**; on the four of
them kell handled cheaply, **-71%** ($0.22 vs $0.75 at Opus's measured costs). The two Opus kept cost about what Opus
alone would (clean up: the same; type hints: +$0.08 for the rejected tries).

Over all ten, with Opus's cost estimated for the four not measured (typo ~$0.12, script ~$0.25, error message ~$0.40
like the type hints, "yes do it" ~$0.03): kell **$1.27** vs Opus **~$2.30**, **about -45%**. By kind:

| Kind of turn | Handled cheaply | Typical cost | vs Opus |
|---|---|---|---|
| chat / approvals | all | < $0.01 | ~-75% |
| questions about the code | 3 of 3 | $0.02-0.07 | -67 to -87% |
| changes with a false premise | 2 of 2 (finding, or a reviewed addition) | $0.04-0.09 | ~-40 to -65% |
| clear changes (script, error message) | 2 of 2 | $0.015-0.16 | ~-60 to -94% (Opus estimated) |
| vague or large edits | 0 of 2 | Opus's own + up to $0.08 | 0 to +19% |

Not counted: these are API-priced; on a Claude subscription the saving is in usage limits, not dollars.

## 5. Timing

- The budgets held everywhere: the longest dispatch (the error message, 1119 s) used the hand-in at 765 s, its
  answer was checked and accepted, and it ended inside the 1200 s hook limit. The check reserve, sized from the suite's
  measured time, was 321 s.
- Answers: 25-210 s (questions that need reading: 58-202 s, against Opus's 113-271 s).
- Changes: 264-549 s for the small ones; **18 minutes for the vague error-message change**, where Opus alone would
  likely take a few minutes. That is the weak spot left: the cheap models are slow per step on General Compute today
  (gemma's first token 7+ s; glm ~9 s per step), and every passing answer is run through a 2.5-3.5 min suite.
- The other tries do stop the moment one answer is accepted (dispatch cancels them); they also stop now on a confirmed
  finding and after two review rejections.

## 6. Open

- The review is not consistent on a request with a false premise: "add --dry-run to the example" was rejected for
  inventing an example in one run and accepted in the next. Both readings are defensible; the same request should not
  flip.
- JEV called a bare "yes do it" a change; kell now corrects that on the client. The server prompt should say an
  approval needs something earlier to approve (next server deploy).
- General Compute answers some plain-text requests with "Invalid base64 image data" (gemma, twice): their bug; kell
  treats it as no verdict and moves on.
- Vague, wide edits take 15-18 minutes: a shorter limit for tasks the judge marks vague, or the related tests before
  the full suite, would cut it.
