# S26 — Navigate an OKF knowledge wiki without loading the whole folder

- **Source:** github.com/coleam00/cole-medin-knowledge-base @ `main@HEAD` (SHA not pinned)
- **License:** NONE stated (content synthesized from public YouTube; each page cites sources). **Treat as not redistributable.**
- **Locator:** `index.md` + `SCHEMA.md`; §"Use it with an agent (copy-paste)"

## problem
An agent given a folder of knowledge markdown tends to load all of it, blowing context; or it answers without citations.

## goal
Answer a question from a structured knowledge base, loading only the pages the question needs, with source citations.

## preconditions
- Git installed; agent filesystem access.

## steps
1. Clone the KB next to the project (`git clone …cole-medin-knowledge-base.git`).
2. Read `index.md`, then `SCHEMA.md`.
3. Navigate the "OKF way": read the index, follow relative links into `concepts/`, `entities/`, `sources/`; open only the pages a question needs — do not load the whole folder.
4. Answer from the KB and cite the concept/entity pages used and the source video(s).
5. Cross-check cited timestamps against `raw/` transcripts.

## decision points
- Question spans many concepts → still open pages one at a time as the reasoning requires them.
- No relevant page → say so; don't answer from outside the KB.

## postconditions
- Answer is grounded in specific KB pages with video + timestamp citations.

## verification
- `lint.py` gates conformance/orphans; cited timestamps match the transcripts in `raw/`.

## failure/recovery
- Citation doesn't check out → re-open the source page; the concept page may be stale vs the transcript.

## implementation
Plain markdown + YAML + a `lint.py` integrity gate; agent navigates via relative links. Zero RAG stack, no API keys.
