# S49 — Define a verifiable business-automation task (AutomationBench)

## problem
"Did the agent do the business workflow right?" is usually a subjective human judgement — not reproducible, not scalable.

## goal
Define a business-automation task such that completion can be checked programmatically, and score it with partial credit.

## preconditions
- A simulated business environment across the ~47 SaaS tools; a target workflow; a set of assertions describing the correct final state.

## steps
1. Instantiate the simulated environment (CRM, marketing, support, finance, HR tools).
2. Supply the trigger data (initial context the workflow reacts to).
3. Let the agent act via the domain-specific tools.
4. Compare the final environment state against the expected state using assertions.
5. Score: `partial_credit` = fraction of assertions satisfied (0.0–1.0); `task_completed_correctly` = 1.0 only if **every** assertion passes, else 0.0.
6. **Exclusion rule:** if a task cannot be checked automatically, it does not belong in the benchmark.

## decision points
- Assertion can't be made programmatic → rewrite the task or drop it; don't accept a manual check.
- Multiple valid end states → assert on the invariants they share, not one exact state.

## postconditions
- A task = {environment spec, trigger data, available tools, assertion set}; runs produce `partial_credit` + `task_completed_correctly`.

## verification
- A reference solution scores `task_completed_correctly = 1.0`; a no-op scores near 0.

## failure/recovery
- Reference solution fails an assertion → the assertion encodes an over-strict expectation; fix the assertion.

## implementation
Python (`automationbench/`) + a `visualizer/`; deterministic assertion-based scoring over a simulated environment.

## source evidence
> "All tasks must be programmatically verifiable. If we can't automatically check whether a task was completed correctly, it doesn't belong in the benchmark."; result fields `partial_credit` (0.0–1.0), `task_completed_correctly` (0.0 or 1.0).
