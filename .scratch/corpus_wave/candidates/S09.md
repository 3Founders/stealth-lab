# S09 — RED-GREEN-REFACTOR TDD loop (superpowers)

- **Source:** github.com/obra/superpowers @ `main@b36e0829` (v6.3.0) · MIT
- **Locator:** `skills/testing/test-driven-development/SKILL.md`; README §"The Basic Workflow"

## problem
Code written before its test tends to be untestable, over-built, and unverified against a real failure.

## goal
Implement each change through a strict RED-GREEN-REFACTOR cycle, retaining no code that predates its test.

## preconditions
- Implementation plan approved/assigned; clean green test baseline.

## steps
1. Write a failing test first (RED).
2. Watch the test fail — confirm it catches a real problem.
3. Write the minimal code to pass the test (GREEN).
4. Watch the test pass.
5. Refactor without breaking tests.
6. Commit the change (atomic).
7. Delete any code that was written before its corresponding test.

## decision points
- Test passes immediately at step 2 → it's not exercising the new behavior; fix the test.
- Refactor breaks a test → stop, revert the refactor, do it smaller.

## postconditions
- All tests pass; changes in atomic commits; no untested code retained.

## verification
- "Watch it fail, write minimal code, watch it pass, commit."

## failure/recovery
- Mid-cycle discovery that the design is wrong → drop to the brainstorming skill, re-plan, restart the cycle.

## implementation
Discipline over the test runner + `git`. Sibling skills: systematic-debugging (4-phase), using-git-worktrees, subagent-driven-development.
