# S16 — Interview-driven agentic-workflow design

## problem
People jump straight to writing a workflow and get the trigger, permissions, or network egress wrong.

## goal
Design a new agentic workflow through a structured interview, then compile it and open a PR.

## preconditions
- Interview phases complete: goal, trigger, tools, permissions, safe-outputs, network. Intent + architecture decided.

## steps
1. Map intent to an event type using the trigger decision matrix.
2. Keep the agent job read-only; route writes only through permitted safe-outputs actions.
3. Infer required network egress from the repository manifests.
4. Author the prompt: state intent, evidence, effects, and noop conditions.
5. `create .github/workflows/<workflow-id>.md`.
6. `compile with gh aw compile <workflow-id>`.
7. `fix all compile errors`.
8. `create a PR with the workflow file and .lock.yml`.

## decision points
- Ambiguous trigger → consult the decision matrix, don't guess.
- Unclear egress → derive it from manifests (package.json, go.mod, …), default deny.

## postconditions
- Workflow compiles cleanly; PR opened with the `.md` + `.lock.yml`.

## verification
- No compile errors; Design Checklist satisfied; PR contains both files.

## failure/recovery
- Compile fails after PR → push a fix commit; the `.lock.yml` regenerates.

## implementation
A designer prompt file consumed by a coding agent + `gh aw compile`. Deterministic compile step.
