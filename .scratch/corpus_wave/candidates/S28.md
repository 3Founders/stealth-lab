# S28 — Select and adapt a pre-built HTML presentation template

- **Source:** github.com/zarazhangrui/beautiful-html-templates @ `main@e5e204fb` · MIT
- **Locator:** `AGENTS.md` + `index.json` (34 `templates/` dirs)
- **Confidence:** low — selection workflow documented in `AGENTS.md`, not quoted here as numbered steps.

## problem
Generating a good-looking deck from scratch is slow; a curated template gets you 90% there if you can pick the right one.

## goal
Match a brief to the best-fit template and adapt it with the user's content.

## preconditions
- Git access; ability to read JSON metadata; basic HTML/CSS.

## steps
1. Clone the repo.
2. Read `AGENTS.md` for operating instructions.
3. Parse `index.json` to understand each template's metadata/capabilities.
4. Match the user's brief to the best-fit template.
5. Copy that template directory.
6. Populate placeholders with the user's content; adjust assets (fonts/images/CSS).

## decision points
- Two templates fit → prefer the one whose metadata matches more of the brief's constraints (length, tone, media).

## postconditions
- A populated, presentation-ready HTML deck derived from a known template.

## verification
- Rendered HTML displays correctly; all placeholders filled; template styling intact.

## failure/recovery
- Content doesn't fit the template's structure → pick a different template rather than distorting this one.

## implementation
Static template gallery + `index.json` metadata; agent does match + copy + populate. Deterministic once a template is chosen.
