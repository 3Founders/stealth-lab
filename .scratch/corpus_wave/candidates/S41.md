# S41 — Query the OpenAlex works API with filters + cursor pagination

- **Source:** openalex.org — docs at help.openalex.org / the API recipes; endpoint `api.openalex.org/works`
- **License:** OpenAlex data is **CC0**. Polite pool via `mailto`.
- **Confidence:** medium — help.openalex.org redirect gave the recipes pointer; procedure grounded in the stable `/works` contract.

## problem
You need bulk scholarly metadata (works, authors, citations) for research-lane checks, without scraping and without hitting rate limits.

## goal
Retrieve a filtered, complete list of works from OpenAlex, paged efficiently, as a good API citizen.

## preconditions
- An email address for the polite pool; a filter expression.

## steps
1. `GET https://api.openalex.org/works?filter=<field>:<value>&per_page=200&mailto=<email>`.
2. Add `&cursor=*` on the first request.
3. Read `meta.next_cursor` from the response.
4. Repeat with `&cursor=<next_cursor>` until `next_cursor` is null.
5. For aggregates use `group_by=<field>`; for a single entity use its OpenAlex ID (`/works/W...`).

## decision points
- Small result set → offset paging (`page=`) is fine; large → cursor paging (avoids the 10k offset ceiling).
- Need counts only → `group_by` with `per_page=1`.

## postconditions
- The full matching set retrieved as JSON pages; no page skipped or duplicated.

## verification
- Sum of page lengths equals `meta.count`; `next_cursor` terminates at null.

## failure/recovery
- 429 / throttling → you omitted `mailto`; add it (polite pool) and back off.

## implementation
Plain HTTPS GET loop; deterministic. No SDK required. Provider: any HTTP client.
