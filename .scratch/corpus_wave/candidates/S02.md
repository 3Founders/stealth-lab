# S02 — Eval-driven skill authoring loop

- **Source:** github.com/anthropics/skills `/skills/skill-creator` @ `main@53048666` · Apache-2.0
- **Locator:** `skills/skill-creator/SKILL.md` §"Creating a skill" / "Running and evaluating test cases"

## problem
A hand-written skill often overfits its examples or fails to trigger; there is no signal on whether it actually helps versus no skill.

## goal
Create a skill and prove, against a baseline, that it improves task outcomes — then iterate until feedback is empty.

## preconditions
- Clear intent for the skill (task, trigger, output format).
- Subagents available (or sequential fallback); Python env for the scripts; a workspace dir.

## steps
1. Capture intent — what it does, when it triggers, expected output, whether test cases apply.
2. Interview & research — edge cases, I/O formats, example files, success criteria, dependencies.
3. Write `SKILL.md` — name, "pushy" description, compatibility, body < ~500 lines.
4. Create 2–3 test-case prompts in `evals/evals.json`.
5. Spawn all runs (with-skill AND baseline) in the same turn → `iteration-<N>/eval-<ID>/{with_skill,without_skill}/outputs/`.
6. Draft objective assertions while runs proceed (`eval_metadata.json`).
7. Capture timing (`total_tokens`, `duration_ms`) → `timing.json`.
8. Grade with `agents/grader.md` → `grading.json`; aggregate via `python -m scripts.aggregate_benchmark <ws>/iteration-N --skill-name <n>`; launch `eval-viewer/generate_review.py`.
9. Read `feedback.json`.
10. Improve the skill (generalize, keep lean, explain why, bundle repeated helpers to `scripts/`).
11. Iterate into `iteration-<N+1>/` with `--previous-workspace` until feedback is empty.
12. (optional) description optimization: `python -m scripts.run_loop --eval-set <trigger-eval.json> --skill-path <skill> --model <id> --max-iterations 5`.
13. (optional) `python -m scripts.package_skill <folder>` → `.skill`.

## decision points
- New skill → baseline = no skill; improvement → baseline = previous skill version.
- Assertions must be objective & discriminating; drop high-variance ones.

## postconditions
- Skill tested vs baseline with pass-rate / timing / token benchmarks; user feedback captured; optionally packaged.

## verification
- `feedback.json` shows satisfaction or is empty; benchmark shows an improvement delta; transcripts show generalization beyond the eval examples.

## failure/recovery
- No delta over baseline → the skill isn't earning its context; cut or refocus.
- Assertions don't discriminate with/without → rewrite them before trusting the score.

## implementation
Orchestration over subagents + Python scripts (`aggregate_benchmark`, `run_loop`, `package_skill`) + an HTML review viewer. Deterministic harness around non-deterministic runs.
