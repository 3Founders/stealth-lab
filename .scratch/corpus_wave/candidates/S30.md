# S30 — Drive a browser from the CLI via stable element refs

- **Source:** github.com/vercel-labs/agent-browser @ `main@eb05921b` (v0.36.0) · Apache-2.0
- **Locator:** `README.md` §"Quick Start"

## problem
Agent browser automation via raw selectors is brittle; selectors drift and overlays silently block clicks.

## goal
Navigate a page, enumerate interactive elements as stable refs, and interact with them reliably.

## preconditions
- `node`/`npm`; Chrome downloaded via `agent-browser install`; target URL reachable.

## steps
1. `npm install -g agent-browser`.
2. `agent-browser install` (downloads Chrome).
3. `agent-browser open https://example.com`.
4. `agent-browser snapshot -i` → returns element refs (`@e1`, `@e2`, …).
5. `agent-browser click @e2` / `agent-browser fill @e3 <value>`.
6. `agent-browser snapshot -i` to capture the updated state.
7. `agent-browser close`.

## decision points
- Ref click blocked → the error names the covering element; dismiss the overlay, re-snapshot, retry.
- Multi-step form → snapshot between steps so refs stay valid after DOM changes.

## postconditions
- Interactions performed against stable refs; session closed.

## verification
- `--json` output confirms per-command success/failure; the post-interaction snapshot reflects the change.

## failure/recovery
- Refs stale after a navigation → re-snapshot; refs are per-DOM-state.

## implementation
Node CLI wrapping Chrome DevTools; deterministic ref assignment; cookie-import auth; iOS-simulator targets. Provider: `agent-browser`.

## source evidence
> "Get snapshot with refs…Use refs to interact…When a ref click is blocked by an overlay, the error includes the covering element."
