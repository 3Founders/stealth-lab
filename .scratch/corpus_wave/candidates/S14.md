# S14 — One rule set across all AI tools + CI enforcement

- **Source:** github.com/maweis1981/agents-md @ `main@1eeb5ef5` · MIT
- **Locator:** `templates/AGENTS.md` §"Option A" + `STANDARDS.md` + `scripts/` + `.github/workflows/lint.yml`

## problem
Claude Code reads `CLAUDE.md`, Codex/Cursor read `AGENTS.md`; teams end up with divergent, unenforced rules per tool.

## goal
Make every AI coding tool read a consistent rule set, and make commit/branch policy machine-enforced in CI.

## preconditions
- Git repo initialized; `curl` available; write access to repo root.

## steps
1. `curl -L https://raw.githubusercontent.com/maweis1981/agents-md/main/templates/AGENTS.md -o AGENTS.md`.
2. Customize the tool-specific sections (Claude Code → `CLAUDE.md`; Codex/Cursor → `AGENTS.md`).
3. Place the files at the repo root for agent auto-discovery.
4. Reference the upstream `STANDARDS.md` as the canonical ruleset.
5. Run the `scripts/` linters to enforce Conventional Commits + branch naming.
6. Wire the lint checks into CI via the GitHub Actions workflow template.

## decision points
- Team uses only one tool → still keep `STANDARDS.md` as the single source; skip the other tool's file.

## postconditions
- All tools read consistent rules on startup; commit format + branch policy enforced by CI.

## verification
- Agent uses `ai/<feature>` branch names, squash merges, no direct pushes to main; commitlint passes in CI.

## failure/recovery
- CI lint flakes → the rule regexes are too strict; loosen in `STANDARDS.md`, not per-repo.

## implementation
Markdown templates + shell lint scripts + a GitHub Actions workflow. Deterministic CI checks.

## source evidence
> "Both files reference the canonical `STANDARDS.md` and contain the minimum rules the agent must follow." — `templates/AGENTS.md` §"Option A".
