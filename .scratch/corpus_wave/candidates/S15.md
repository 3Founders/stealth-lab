# S15 — Compile a natural-language workflow into an executable GitHub Actions workflow

- **Source:** github.com/github/gh-aw @ `main@957471c2` · MIT
- **Locator:** `.github/aw/github-agentic-workflows.md` + docs quick-start

## problem
Repo automation that needs an LLM is hard to write safely as raw Actions YAML; permissions and write-safety are easy to get wrong.

## goal
Turn a Markdown workflow definition into a sandboxed, compiled `.lock.yml` GitHub Actions workflow.

## preconditions
- GitHub CLI installed; repo write access; an AI engine chosen (Copilot / Claude / OpenAI / Gemini / Pi).

## steps
1. `gh extension install github/gh-aw`.
2. Create a `.md` workflow file with YAML frontmatter in `.github/workflows/` (or `.github/aw/`).
3. Define frontmatter: triggers, permissions, tools, AI engine.
4. Write the Markdown body — the agent task.
5. `gh aw compile` → produces `.lock.yml` in `.github/workflows/`.
6. Fix all compile errors.
7. Commit + push the `.md` and `.lock.yml`; the trigger fires the run.
8. Review results via safe-outputs jobs (validated writes, scoped permissions).

## decision points
- Any repository write needed → declare it as a `safe-outputs` action, never a direct write from the agent job.
- Pin `gh-aw` outside the retired range `>=0.83.3,<0.85.4` (GHSA-8h78-hpm7-29gg).

## postconditions
- `.lock.yml` committed; workflow runs on its trigger; agent job read-only by default; writes buffered through safe-outputs.

## verification
- `.lock.yml` present in `.github/workflows/`; Actions run succeeds; agent reasoning visible in job logs.

## failure/recovery
- Compile errors → fix frontmatter/body and recompile; never hand-edit `.lock.yml`.

## implementation
Go compiler (`gh aw compile`) → GitHub Actions YAML; agent engines pluggable; gVisor sandbox; safe-outputs jobs apply writes.

## source evidence
