# S04 — Review UI code against the Web Interface Guidelines

- **Source:** github.com/vercel-labs/agent-skills `/skills/web-design-guidelines` @ `main@063bee9` · MIT
- **Locator:** `skills/web-design-guidelines/SKILL.md` §"How It Works"

## problem
UI/UX quality checks are inconsistent and rely on whatever the reviewer remembers; guidance drifts from the canonical source.

## goal
Produce a compliance review of specified UI code against the current Web Interface Guidelines, in a terse actionable format.

## preconditions
- User supplies a file/pattern or explicitly asks for a review.
- WebFetch capability available.

## steps
1. Fetch the latest guidelines from `https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md`.
2. Read the specified files, or request a file/pattern from the user.
3. Check the code against **all** rules in the fetched guidelines.
4. Output findings in the terse `file:line` format.

## decision points
- No target supplied → ask for a file/pattern rather than guessing.
- Rule ambiguous for the framework in use → note the ambiguity in the finding, don't drop it.

## postconditions
- Findings delivered as `file:line` entries, each tied to a specific rule.

## verification
- Every fetched rule was applied; output conforms to the `file:line` shape.

## failure/recovery
- Guidelines fetch fails → stop; do not review against a stale/embedded copy.

## implementation
Deterministic: fetch → iterate rules → emit findings. Provider: agent with WebFetch.
