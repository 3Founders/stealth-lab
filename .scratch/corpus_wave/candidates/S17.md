# S17 — Full agentic-workflow lifecycle (create → compile → iterate → run)

- **Source:** github.com/github/gh-aw `/docs/src/content/docs/setup/creating-workflows.mdx` @ `main@957471c2` · MIT
- **Locator:** frontmatter title "Create a GitHub Agentic Workflow"

## problem
Teams want a repeatable path from "idea for automation" to "running workflow", across the GitHub web UI, VS Code, or manual editing.

## goal
Take a workflow from natural-language intent to a merged, running `.lock.yml`, in whichever surface the author uses.

## preconditions
- A repo; access to Copilot / a coding agent / VS Code Agent Mode; ~5–15 min depending on complexity.

## steps
1. In the repo's "Agents" tab (or a coding agent), prompt: *"Create a workflow for GitHub Agentic Workflows using https://raw.githubusercontent.com/github/gh-aw/main/create.md"* + the workflow's purpose.
2. Let the agent ask clarifying questions and generate the `.md` source (frontmatter + body).
3. Compile it (`gh aw compile`) — fix errors.
4. Iterate on the body/frontmatter until it compiles and reads correctly.
5. Merge the `.md` + `.lock.yml`.
6. Monitor runs in the Actions tab; review safe-output diffs.

## decision points
- Web UI vs VS Code vs manual → same source format; choose by where the author is comfortable.
- Start from a template prompt (issue-triage / activity-report / doc-updater) when the intent matches.

## postconditions
- Compiled workflow merged and firing on its trigger; runs observable in Actions.

## verification
- The workflow compiles; a real run completes; safe-outputs behave as declared.

## failure/recovery
- Generated workflow over-permissioned → re-prompt with explicit least-privilege + safe-outputs.

## implementation
Coding agent + `create.md` reference prompt + `gh aw compile`; runs on GitHub Actions.
