## problem
Unlabeled and partially-labeled issues pile up; manual triage doesn't scale and slips.

## goal
Keep issues labeled by type and component automatically, safely, with a bounded budget.

## preconditions
- A `gh-aw`-enabled repo; an AI engine configured; `GH_AW_*` token secrets.

## steps
1. Trigger on `issues: [opened, edited]` + a `schedule` cron + `workflow_dispatch`.
2. A `steps:` block runs `gh api` to fetch unlabeled issues and type-only issues missing component labels into `/tmp/gh-aw/agent/`.
3. The agent job (read-only, gVisor sandbox, `min-integrity: approved` github toolset) proposes labels.
4. Apply via `safe-outputs`: `add-labels` (max 10) + one `create-discussion` audit ("[Auto-Triage] ", category "audits", close older).
5. `noop:` when there's nothing to label.
6. `evals:` grade the run (e.g. "labels-applied": did it label an unlabeled issue, or correctly noop?).

## decision points
- No unlabeled issues → `noop`, don't manufacture activity.
- Budget: `max-daily-ai-credits: 10000`, `user-rate-limit` 5 runs / 60 min.

## postconditions
- Newly-triaged labels applied; one audit discussion; run graded by evals.

## verification
- `safe-outputs` job shows the label writes; the eval question passes; agent job logs show read-only perms.

## failure/recovery
- Wrong labels → tighten the agent prompt / label taxonomy; safe-outputs cap limits blast radius to 10.

## implementation
Compiled gh-aw workflow: `gh api` fetch steps + agent engine (`pi`/`openai gpt-5.4`) + gVisor sandbox + safe-outputs + evals. Deterministic wiring around a non-deterministic labeling step.
