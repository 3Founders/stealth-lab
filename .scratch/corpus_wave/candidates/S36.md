# S36 — Construct and verify a SWE-bench task instance

- **Source:** github.com/SWE-bench/SWE-bench @ `main@02e7a74f` · MIT
- **Locator:** `README.md` + docs; task-instance schema (`patch`, `test_patch`, `FAIL_TO_PASS`, `PASS_TO_PASS`)

## problem
Evaluating whether an agent "fixed a real issue" needs an objective, reproducible pass/fail — not a human eyeballing a diff.

## goal
Turn a real merged PR into a verifiable task instance, and define exactly when a candidate patch resolves it.

## preconditions
- A GitHub repo with a merged PR that closes an issue and adds/updates tests; a buildable environment for that commit.

## steps
1. Take the merged PR that fixes the issue.
2. Separate the fix patch from its `test_patch` (the test changes).
3. Record `FAIL_TO_PASS` — tests that fail before the fix and pass after.
4. Record `PASS_TO_PASS` — tests that pass both before and after (regression guard).
5. Build a reproducible environment (image) pinned to the base commit.
6. Score a candidate patch: apply it + the `test_patch`; it **resolves** the instance iff every `FAIL_TO_PASS` now passes AND every `PASS_TO_PASS` still passes.

## decision points
- Flaky test in `FAIL_TO_PASS` → exclude it or the instance is unreliable (SWE-bench Verified is the human-confirmed-solvable subset).
- Environment won't build → the instance can't be used.

## postconditions
- A task instance = {problem statement, base commit, `test_patch`, `FAIL_TO_PASS`, `PASS_TO_PASS`, env spec}.

## verification
- The gold patch resolves the instance; an empty patch does not.

## failure/recovery
- Non-determinism in scoring → pin the env and test seeds; re-run to confirm stability.

## implementation
`swebench` Python package; Docker/Modal execution; deterministic test-based scoring. Provider: SWE-bench harness.

## source evidence
> "SWE-bench: Can Language Models Resolve Real-World GitHub Issues?"; "SWE-bench Verified! … A subset of 500 problems that real software engineers have confirmed are solvable."
