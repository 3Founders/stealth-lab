# S11 — Scaffold an autonomous maintenance loop

- **Source:** github.com/cobusgreyling/loop-engineering @ `main@fd0a946f` · MIT
- **Locator:** `docs/QUICKSTART.md` + `patterns/registry.yaml`; CLI `@cobusgreyling/loop`

## problem
People keep hand-prompting an agent for recurring maintenance; there is no repeatable "system that prompts the agents" and no measure of readiness.

## goal
Stand up a named maintenance loop in a repo that discovers work, hands it to an agent, verifies results, and persists state — starting report-only.

## preconditions
- A git repo; `npx` available; a chosen pattern (e.g. `daily-triage`) and tool (`claude`/`grok`/`codex`/`opencode`).

## steps
1. `npx @cobusgreyling/loop init . --pattern daily-triage --tool claude`.
2. `npx @cobusgreyling/loop doctor .` — audit + sync + top-3 actions; read the "Loop Ready" score.
3. Week one: run **report-only** — no auto-fix, no auto-merge. Read what the loop writes.
4. Adjust the pattern / `STATE.md` from `patterns/registry.yaml`.
5. Only after review, promote the loop to take actions.

## decision points
- Feature/refactor work → use the refactor path, not `daily-triage` (don't point triage at a whole-repo rewrite).
- Unsure which pattern → use the interactive pattern picker on the showcase.

## postconditions
- Loop scaffolded (`STATE.md`, schedule wiring); "Loop Ready" score recorded; first runs are report-only artifacts.

## verification
- `loop doctor` score climbs; the report-only runs produce inspectable output before any action is taken.

## failure/recovery
- Loop proposes noisy/wrong actions → stay in report-only, tune the pattern; never promote an unreviewed loop.

## implementation
Node CLI (`@cobusgreyling/loop`) scaffolds pattern files + scheduling (native `/loop`, cron, or GitHub Action). Deterministic scaffold; the loop body calls a coding agent.
