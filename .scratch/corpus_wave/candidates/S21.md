# S21 — Bootstrap only task-relevant context at session start

- **Source:** github.com/rmolines/context-engineering @ `master@HEAD` (SHA not pinned) · MIT
- **Locator:** `ARCHITECTURE.md` §"The philosophy" + the `/bootstrap` command

## problem
Each new session re-explains the project; prior decisions and progress are lost or must be re-narrated, wasting context on things the model already "knew".

## goal
At session start, load exactly the context this session needs — prior decisions, open work, domain facts — without loading everything.

## preconditions
- Project initialized once (`/init`); GitHub connection configured; a place decisions are persisted (Issue comments).

## steps
1. Run `/bootstrap` at the start of each session.
2. Live GitHub query (GraphQL) for the relevant Issues + their comments.
3. Load domain context (`.claude/docs/`) — briefing + alignment.
4. Read the saved Issue comments from the prior session.
5. Present a continuation briefing to the user.
6. During the session, persist new decisions back as Issue comments.

## decision points
- Load a doc/issue only if the current task references it — don't pull the whole folder.
- If no prior session state exists, start clean rather than fabricating continuity.

## postconditions
- Session context reflects prior decisions/progress; no architecture re-explanation needed.

## verification
- The briefing shows real prior-session state from Issue comments; domain docs are reachable on demand.

## failure/recovery
- Briefing is stale/wrong → the persistence step was skipped last session; write decisions as comments going forward.

## implementation
Claude Code slash commands + hooks; GitHub GraphQL for state; markdown domain docs. Deterministic retrieval.

## source evidence
> "facts about your codebase matter more than instructions about behavior"; "It configures and optimizes Claude Code's native context layers (CLAUDE.md, rules, memory, hooks) … doesn't replace any of that — it **manages** it."
