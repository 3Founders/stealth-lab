# S24 — Trim MCP tool context to task-relevant, then confirm sufficiency

- **Source:** github.com/ch040602/Save-The-Token @ `main@HEAD` (SHA not pinned) · MIT
- **Locator:** `docs/benchmark.md` §"Measured Context Savings With Sufficiency Checks"

## problem
Every configured MCP server injects its full tool schemas + instructions into context, most of which is irrelevant to the task at hand.

## goal
Produce a client-specific tool allowlist trimmed to a token budget for a named task, without losing the ability to complete that task.

## preconditions
- MCP config files present (`.mcp.json` etc.); Python 3.11+; optional instruction files (`AGENTS.md`, `CLAUDE.md`).

## steps
1. `save-the-token scan --root .` — discover + lint agent MCP config files.
2. `save-the-token tools --root . --budget 8000 --schema-digest` — measure + digest tool schemas.
3. `save-the-token report --root . --budget 8000 --task "fix tests" --route-instructions --compress-instructions --order-evidence`.
4. `save-the-token slim --root . --budget 8000 --task "review GitHub issues"` — print compact client-specific tool allowlist snippets.
5. Apply the allowlist; re-run the sufficiency check.

## decision points
- Budget too tight for a real task → the sufficiency check fails; raise the budget rather than ship a crippled allowlist.

## postconditions
- Client-ready allowlist snippets + a sufficiency report with token counts.

## verification
- "All five full-sufficient cases retained sufficiency after reduction" — the reduced context still lets the task complete.

## failure/recovery
- Task fails with the slimmed set → a needed tool was cut; widen the allowlist for that task class.

## implementation
Python CLI: config scan + schema measurement + task-routed instruction routing + compression; deterministic. Provider: `save-the-token`.

## source evidence
> "69.3% weighted average" saving on successful cases; "100.0% success on eligible cases" — `docs/benchmark.md`.
