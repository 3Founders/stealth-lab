# S50 — Build and evaluate a tool-use task (ToolBench / DFSDT + ToolEval)

- **Source:** github.com/OpenBMB/ToolBench @ `master@d56fdd89` · Apache-2.0 (paper arXiv:2307.16789, ICLR'24)
- **Locator:** `README.md`; `data/toolenv/tools/`; `toolbench/tooleval/`; `toolbench/inference/qa_pipeline.py`

## problem
Training/evaluating general tool use needs many real APIs, instructions that actually require them, and an objective score for a multi-step solution path.

## goal
Construct a tool-use task with an annotated solution path, and evaluate a candidate's tool-use with reproducible metrics.

## preconditions
- A pool of real APIs (ToolBench uses 16,464 REST APIs from RapidAPI); a capable LLM for instruction + path generation.

## steps
1. **API collection:** gather real REST APIs into `data/toolenv/tools/`.
2. **Instruction generation:** curate instructions covering single-tool and multi-tool scenarios.
3. **Solution-path annotation:** run a depth-first search based decision tree (**DFSDT**) so the model can explore/backtrack across tool calls, producing an annotated action sequence.
4. **Evaluation (ToolEval):**
   - **Pass Rate** — fraction of instructions successfully completed.
   - **Preference / Win Rate** — pairwise comparison of two answer (action) sequences against a reference.

## decision points
- Chain-of-thought / linear planning fails on hard multi-tool tasks → DFSDT (backtracking) is the point; don't fall back to linear.
- Reporting a single number → give both Pass Rate and Win Rate; they measure different things.

## postconditions
- A task = {instruction, tool set, DFSDT-annotated solution path}; ToolEval yields Pass Rate + Win Rate for a candidate.

## verification
- ToolEval documented ~87.1% pass-rate / ~80.3% win-rate agreement with human judgement (the metric itself is validated).

## failure/recovery
- Pass Rate high but Win Rate low → the model completes tasks inefficiently/inelegantly; inspect the action sequences.

## implementation
Python: `toolbench/inference/qa_pipeline.py` (DFSDT inference) + `toolbench/tooleval/` (Pass/Win). Deterministic eval given fixed references. Provider: ToolBench.
