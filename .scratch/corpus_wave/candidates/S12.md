# S12 — Author an AGENTS.md repository bootstrap

- **Source:** github.com/agentsmd/agents.md @ `main@6ae22720` · MIT
- **Locator:** `AGENTS.md` (spec) + the site's worked example

## problem
Every AI coding agent re-derives project setup, test commands, and PR conventions from scratch, inconsistently.

## goal
Give agents one predictable file at the repo root carrying the context and instructions they need.

## preconditions
- An active project; planned agent usage.

## steps
1. Create `AGENTS.md` in the project root.
2. Add a "Dev environment tips" section — setup commands, navigation shortcuts.
3. Add a "Testing instructions" section — CI/test commands.
4. Add a "PR instructions" section — commit/PR conventions.
5. (optional) add build-failure troubleshooting and required lint/type-check commands.
6. For a monorepo, add a nested `AGENTS.md` per package — the nearest one wins.

## decision points
- Package-specific rules diverge → nested `AGENTS.md`, don't overload the root.

## postconditions
- A single predictable guidance file at the repo root (plus nested ones where needed).

## verification
- Sections match the spec example ("Dev environment tips", "Testing instructions", "PR instructions"); an agent picks up the nearest file.

## failure/recovery
- Agent ignores it → it's likely missing the trigger-relevant commands; add explicit test/lint commands.

## implementation
Plain markdown convention; consumed by AGENTS.md-aware agents (Codex, Cursor, …). No runtime.
