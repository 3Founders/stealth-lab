# S33 — Client-side form validation with the Constraint Validation API

- **Source:** github.com/mdn/content @ `main@HEAD` (SHA not pinned) · content CC-BY-SA 2.5 (attribute "MDN Web Docs contributors"); tooling MPL-2.0
- **Locator:** `files/en-us/web/html/guides/constraint_validation/index.md` (slug `Web/HTML/Guides/Constraint_validation`)

## problem
Forms submit invalid data, or roll bespoke validation that diverges from browser behavior and misses accessibility.

## goal
Validate form input in the browser using HTML attributes + the Constraint Validation API, with visible feedback, before submission — and still validate server-side.

## preconditions
- An HTML form with input elements; optionally JavaScript for custom rules.

## steps
1. Apply HTML constraint attributes: semantic `type` (`email`, `url`, `number`, …), `required`, `minlength`/`maxlength`, `min`/`max`, `pattern`.
2. For rules HTML can't express, use `setCustomValidity()` in JS: set a message when invalid, set `""` when valid.
3. Gate submission with `form.checkValidity()` / element `.checkValidity()`.
4. Style state with the `:invalid` / `:valid` pseudo-classes.
5. Surface errors with `reportValidity()` (or a custom error region).
6. Always also validate the same rules server-side.

## decision points
- Cross-field rule (e.g. confirm-password) → `setCustomValidity` on the dependent field, re-checked on input.
- Custom error UI → suppress the native bubble and mirror `validationMessage` into your region.

## postconditions
- Invalid input is blocked client-side with feedback; server enforces the same constraints.

## verification
- Test invalid + valid inputs; confirm `:invalid` applies and submission is blocked; confirm the server rejects the same bad input.

## failure/recovery
- Valid input rejected → a stale `setCustomValidity` message wasn't cleared to `""` on the valid path.

## implementation
Native browser API + CSS; deterministic. No library. Provider: any web runtime.

## source evidence
> `setCustomValidity("")` / `setCustomValidity("Error message")`; `element.checkValidity()`; `input:invalid { border: 2px solid red; }`; "Always implement server-side validation as backup" — MDN guide.
