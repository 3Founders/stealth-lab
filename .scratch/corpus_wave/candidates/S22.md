# S22 — Output sandboxing to keep command output out of context

- **Source:** github.com/rriordan/claude-code-token-optimization @ `main@HEAD` (SHA not pinned) · MIT
- **Locator:** `README.md` §"Layer 1 — Output sandboxing"
- **Confidence:** low — the repo is patterns, self-described as "not controlled benchmarks".

## problem
Running a command and reading its raw output dumps large, mostly-irrelevant text into context ("40–80% of the context window to noise" — author's illustration, not a measurement).

## goal
Get the answer from a command without the raw output entering the model's context.

## preconditions
- An executable environment; the command's output is processable by code.

## steps
1. Identify bash commands that generate large output.
2. Instead of running a command and reading the output, write code that processes the output.
3. Have the code filter/derive the answer before anything is logged.
4. Return only the derived result to context.

## decision points
- Output small and fully relevant → just read it; sandboxing adds overhead.
- Need the raw output later → write it to a file, return only a pointer + summary.

## postconditions
- Raw output stays in the subprocess; only the derived answer is in context.

## verification
- Measure tokens consumed; confirm the derived output (not the raw stream) is what appears in context.

## failure/recovery
- The derivation is wrong → the filter logic is the bug, not the sandboxing; inspect the intermediate.

## implementation
Discipline over a code-exec tool; deterministic. Provider: coding agent with shell/code execution.
