# S08 — Five-axis code review

- **Source:** github.com/addyosmani/agent-skills `/skills/code-review-and-quality` @ `main@d2c37ef` · MIT
- **Locator:** `skills/code-review-and-quality/SKILL.md` §"The Five-Axis Review"

## problem
Reviews fixate on style nits, miss structural problems, and block changes that would still improve the codebase.

## goal
Decide whether a change should merge, on the standard "approve when it definitely improves overall code health, even if imperfect."

## preconditions
- Change exists with accompanying tests and a description; reviewer understands the task requirements.

## steps
1. Understand the context — intent and expected behavior.
2. Review the tests first — coverage and intent.
3. Review the implementation across five axes: correctness, readability, architecture, security, performance.
4. Categorize findings — Critical / Required / Nit / Optional.
5. Verify the verification — confirm tests, builds, and manual checks passed.

## decision points
- Change > ~1000 lines → ask for a split before reviewing.
- New dependency → evaluate against maintenance, security, bundle impact.

## postconditions
- All Critical resolved; all Required addressed; tests pass; build succeeds; verification documented.

## verification
- Each finding carries a severity label; sign-off records what was checked.

## failure/recovery
- Reviewer can't reproduce the verification → block until it's reproducible.

## implementation
Human/agent judgement over a checklist; deterministic categorization. Provider: reviewing agent.
