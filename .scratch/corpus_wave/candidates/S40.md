# S40 — Build a notebook-analysis execution trajectory

- **Source:** huggingface.co/datasets/jupyter-agent/jupyter-agent-dataset · card rev 2025-04-09 · Apache-2.0
- **Locator:** dataset card; fields `question` / `answer` / `messages` (ChatML) / `files_used` / `packages_used` / `executor_type` / `tools`. ~95,800 rows / 51,389 synthetic notebooks. **Do not download data.**

## problem
Training a notebook agent needs data where a data question is answered by *executing* code over real datasets, with the run preserved.

## goal
Produce a verified question → executed-notebook → answer record from a real Kaggle notebook.

## preconditions
- A corpus of real Kaggle notebooks (deduplicated); a code-generation model; an execution sandbox (E2B or LLM-based).

## steps
1. Ingest a real Kaggle notebook.
2. Quality-filter with an educational-quality scorer (Qwen-32B); drop non-analysis notebooks.
3. Generate a dataset-grounded question + a verified answer (two-step, validated against notebook context).
4. Generate code cells (Qwen-Coder-480B).
5. Execute the cells in the sandbox; keep the executed trace.
6. Store as `messages` (ChatML) with `files_used`, `packages_used`, `executor_type`, `tools`; split `thinking` / `non_thinking`.

## decision points
- Execution fails → discard the record rather than keep an unverified trace.
- Question not answerable from the notebook's data → regenerate the question.

## postconditions
- A record: grounded question, executed code trace, verified answer, environment metadata.

## verification
- The answer is validated against the notebook context; the code actually executed in the sandbox.

## failure/recovery
- Answer drift from re-execution → package/version mismatch; `packages_used` pins it for replay.

## implementation
Synthesis pipeline: Datatrove dedup + quality scorer + QA gen + code gen + E2B/LLM sandbox. Output is a training dataset.
