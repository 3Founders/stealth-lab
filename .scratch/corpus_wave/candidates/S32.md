# S32 — Accessibility audit slice of the Web Interface Guidelines

- **Source:** github.com/vercel-labs/agent-skills `/skills/web-design-guidelines` @ `main@063bee9` · MIT
- **Locator:** `SKILL.md` §"How It Works" — accessibility subset of the fetched guidelines
- Same artifact as S04; this is the a11y-only projection.

## problem
Accessibility rules get lost among general design rules; a focused a11y pass is more actionable.

## goal
Produce `file:line` findings for accessibility violations only, against the current Web Interface Guidelines.

## preconditions
- A UI file/pattern to review; WebFetch available.

## steps
1. Fetch the current guidelines (`…/web-interface-guidelines/main/command.md`).
2. Filter to the accessibility rules: semantics, focus order, visible focus, colour contrast, labels/names, keyboard operability, ARIA correctness.
3. Check the target code against just those rules.
4. Emit `file:line` findings for each a11y violation, citing the rule.

## decision points
- A finding is both a11y and general → report it under a11y (higher severity for this pass).
- Framework component hides the DOM → note the a11y contract the component must uphold.

## postconditions
- A11y-specific findings in `file:line` form, each tied to a rule.

## verification
- Every a11y rule in the fetched set was applied; output is `file:line`.

## failure/recovery
- False positives from a design system → the rule needs a component-level exception noted, not dropped.

## implementation
Same fetch→filter→check→emit as S04, scoped to a11y rules. Provider: agent with WebFetch.
