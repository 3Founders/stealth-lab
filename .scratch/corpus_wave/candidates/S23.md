# S23 — Return diffs, not full file re-reads (smart_read)

- **Source:** github.com/ooples/token-optimizer-mcp @ `master@HEAD` (SHA not pinned) · MIT
- **Locator:** `README.md` §§"Quick start" / "The re-read case"

## problem
Re-reading an unchanged file several times in a session costs its full token size each time ("a 5 KB config read fifteen times … costs far more than one 200 KB file read once").

## goal
Pay the full token cost of a file once; on later unchanged reads, pay only for the diff.

## preconditions
- Node.js 22+; an MCP-capable client.

## steps
1. Install the MCP server: `npx -y @ooples/token-optimizer-mcp@latest`.
2. Call `smart_read` with the file path.
3. The server caches the original content automatically on first read.
4. On subsequent reads of the same path, `smart_read` returns only a diff.
5. Verify savings via `get_session_stats` (or the dashboard).

## decision points
- File changed a lot → the diff approaches full size; that's fine, it's still bounded.
- First-ever read of a huge file → no saving; the win is on re-reads.

## postconditions
- Re-reads of unchanged files return only changed lines; session stats report tokens saved.

## verification
- `get_session_stats` shows a positive token-saved figure on the second+ read of a file.

## failure/recovery
- Diff looks wrong → cache/key mismatch; clear the cache entry and re-read.

## implementation
MCP server: multi-tier cache (L1/L2/L3) + diff computation; deterministic. Provider: `@ooples/token-optimizer-mcp`.

## source evidence
> "Re-reading a file you already read this session returns only a diff—usually the single biggest win"; "A 5 KB config read fifteen times across a session costs far more than one 200 KB file read once."
