# S07 — TDD after discovering the repo's own test conventions

- **Source:** github.com/addyosmani/agent-skills `/skills/test-driven-development` @ `main@d2c37ef` · MIT
- **Locator:** `skills/test-driven-development/SKILL.md` §"Test-Driven Development"

## problem
An agent parachutes into an unfamiliar repo and writes tests in the wrong framework, or with the wrong command, or that never actually ran.

## goal
Implement a change test-first, using the repository's own framework, build system, and commands.

## preconditions
- Access to the repo; a change or bug to implement.

## steps
1. Discover the repo's test framework, build system, and conventions.
2. Identify the focused-test command and the full-suite command for this project.
3. RED — write the test first; it must fail.
4. GREEN — write the minimum code to make it pass.
5. REFACTOR — with tests green, improve without changing behavior.
6. For a bug fix, include a reproduction test that failed before the fix.
7. Run the full suite with the repo's own command.

## decision points
- Multiple test runners present → match the one the target module uses.
- Can't find a focused-test command → fall back to full-suite but note the slowness.

## postconditions
- New behavior has a test; full suite green with the repo's command; no skipped/disabled tests; coverage not decreased.

## verification
- Test names describe expected behavior; the reproduction test demonstrably failed pre-fix.

## failure/recovery
- Test passes before the change → it isn't testing the new behavior; rewrite it.

## implementation
Discipline over the repo's test runner + `git`. Provider: coding agent.
