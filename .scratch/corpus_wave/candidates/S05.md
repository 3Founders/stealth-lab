# S05 — Apply React/Next.js performance rules by priority

- **Source:** github.com/vercel-labs/agent-skills `/skills/react-best-practices` @ `main@063bee9` · MIT
- **Locator:** `skills/react-best-practices/SKILL.md` §"Rule Categories by Priority" + `rules/*`

## problem
React/Next.js perf work is ad hoc; teams apply random tips without ordering by impact or checking the measured effect.

## goal
Systematically apply the 70 rules (8 priority categories) to a codebase, highest-impact first, with a measured before/after.

## preconditions
- Working React/Next.js codebase; an identified bottleneck or review task; access to `rules/`.

## steps
1. Trigger when writing new components/pages or implementing data fetching.
2. Consult category rules by impact level (Priority 1–8).
3. CRITICAL — "Eliminating Waterfalls": use `Promise.all()` for independent operations.
4. Bundle — "Import directly, avoid barrel files"; "Use `next/dynamic` for heavy components".
5. Server — "Use `React.cache()` for per-request deduplication".
6. Client rendering — "Extract expensive work into memoized components".
7. JS patterns — "Use Set/Map for O(1) lookups".
8. Read the detailed `rules/<name>.md` for code examples before implementing.

## decision points
- Fix in priority order; skip a category only with a measured reason.

## postconditions
- Bottlenecks categorized; applicable rules applied with code examples.

## verification
- Reduced request waterfalls; smaller initial bundle; improved hydration — measured, not asserted.

## failure/recovery
- No measured improvement → revert the change; the rule didn't apply to this workload.

## implementation
Guidance + code-transform; deterministic once a rule is chosen. Provider: coding agent with the rule files.
