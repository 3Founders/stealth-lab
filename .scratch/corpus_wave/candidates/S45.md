# S45 — Apply the PyTorch performance-tuning checklist to a training loop

## problem
A training/inference loop is slower than it should be and the team applies random optimizations without ordering or measurement.

## goal
Apply the PyTorch tuning-guide steps in order and measure the effect with the profiler.

## preconditions
- A working PyTorch training or inference loop; a GPU (for the CUDA-specific steps); the profiler available.

## steps
1. Enable async data loading + `pin_memory=True` in the `DataLoader`.
2. For inference, wrap in `torch.no_grad()` / use `inference_mode`.
3. Fuse pointwise ops / enable the cuDNN autotuner (`torch.backends.cudnn.benchmark = True`) for fixed input sizes.
4. Use automatic mixed precision (`torch.autocast`) + a `GradScaler`.
5. Increase batch size; switch tensors to `channels_last` memory format for conv nets.
6. Profile before and after each change with `torch.profiler`; keep changes that measurably help.

## decision points
- Variable input sizes → do NOT enable `cudnn.benchmark` (it re-autotunes and gets slower).
- Memory-bound vs compute-bound → the profiler tells you which; optimize the actual bottleneck.

## postconditions
- A measurably faster loop; each retained change backed by a profiler before/after.

## verification
- `torch.profiler` traces show reduced step time / higher GPU utilization for each kept change.

## failure/recovery
- AMP degrades accuracy → some ops need `float32`; scope `autocast` or exclude those ops.

## implementation
Standard PyTorch APIs; deterministic. The recipe is runnable (`make html` builds it). Provider: PyTorch.
