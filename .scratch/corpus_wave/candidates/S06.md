# S06 — Ship a change as small independently-committable increments

- **Source:** github.com/addyosmani/agent-skills `/skills/incremental-implementation` @ `main@d2c37ef` (v0.6.8) · MIT
- **Locator:** `skills/incremental-implementation/SKILL.md` (25-skill lifecycle library, "Build" phase)

## problem
Large single-shot changes are hard to review, hard to bisect when they break, and often mix unrelated concerns.

## goal
Deliver a feature/fix as a sequence of small commits, each of which builds, passes tests, and stands alone.

## preconditions
- An approved plan / task breakdown.
- Green test baseline; a working build.

## steps
1. Break the change into ~100-line units, each a single concern.
2. Implement unit 1; run the repo's tests; commit atomically.
3. Repeat per unit — never let a commit leave the tree red.
4. Keep refactors in their own commits, separate from behavior changes.
5. Stop and re-plan if a unit balloons past its intended size.

## decision points
- Unit > ~300 lines → split further before committing.
- Discovering hidden coupling → land a small enabling refactor first, its own commit.

## postconditions
- History is a series of green, single-concern commits; each is independently revertible.

## verification
- `git log` shows atomic commits; each commit checked out builds + tests green.

## failure/recovery
- A later commit reveals an earlier one was wrong → revert just that commit, not the batch.

## implementation
Discipline over `git` + the repo's test runner; deterministic. Provider: coding agent.
