# S31 — Eliminate request waterfalls in React/Next.js

## problem
Components `await` independent async operations one after another, so total latency is the sum instead of the max.

## goal
Convert serial awaits of independent operations into parallel ones, on both client and server components.

## preconditions
- A React/Next.js codebase with a measured or suspected latency problem; access to the `rules/` files.

## steps
1. Find sequential `await`s where the later call does not depend on the earlier result.
2. Hoist them into a single `Promise.all([...])`.
3. For server components, lift data fetches to a common parent so they start together ("server-parallel-fetching").
4. For nested layouts, use parallel nested fetching rather than waterfalling through the tree.
5. Re-measure: total time should approach the slowest single call, not the sum.

## decision points
- A call genuinely depends on a prior result → it stays serial; only parallelize the independent ones.
- Too many parallel calls hammering one backend → batch instead.

## postconditions
- Independent fetches run concurrently; request-timeline shows overlap, not a staircase.

## verification
- Network waterfall (devtools / traces) shows concurrent bars; measured page latency drops toward the max single call.

## failure/recovery
- Latency unchanged → the awaits weren't actually the bottleneck; profile before assuming.
