# Borrow permissive headless parts, copy AGPL designs

**No single open-source app gives a Next.js 15 / React 19 static export a ready-made human-plus-agent group chat, so the redesign should be assembled.** Use unstyled headless primitives for the message list, a small custom APG-style mention combobox, and hand-built agent status and pause controls. Start from shadcn's new unstyled chat primitives (`@shadcn/react` message-scroller) or the permissive component kits around them. Use MindRoom, Open WebUI Channels, open-tag, Zulip and Linear's agent guidelines as behavioural references rather than code. The best-looking team-chat UIs are the hardest to reuse. Element's Compound is the best technical fit (React 19 peer, plain CSS) but is AGPL-3.0 or paid, and Signal, Nextcloud Talk and Stoat are AGPL too. The permissive options are Zulip (Apache-2.0, but jQuery/Handlebars with no React), the Mattermost webapp (Apache-2.0, per a model summary of the licence file), Rocket.Chat's Fuselage (MIT, but SCSS plus a CSS-in-JS runtime) and the MIT AI-chat kits. Much of the evidence is thinner than it looks. Several researchers read only search snippets or registry metadata, no UX was checked from screenshots or demos, and no library was tested against React 19 or a static export. Section 4 lists what remains unverified.

## Only a few projects model a room of humans and named agents

Dedicated AI chat UIs (LibreChat, LobeChat, Chainlit, assistant-ui) are single-user chats. The notes did not verify that for every one. The projects that come close to a room are few.

**MindRoom** is the strongest on behaviour. It is a multi-agent runtime on Matrix where each agent is a Matrix account. Tagged agents respond. In threads with two or more people, agents answer only when tagged. A router picks a responder in a new untagged thread. It shows collapsible tool traces, approval cards that list what will be sent and to whom, and `!cancel_job` style commands, but no dedicated stop button was described ([libraries.io](https://libraries.io/pypi/mindroom)). It is Apache-2.0 apart from a BSL 1.1 `saas-platform/` directory. It is Python, with its own web client and a dashboard needing Node 24 and Bun, so it is a design reference and not a drop-in kit.

**Open WebUI Channels** is the only mainstream web UI with multi-user, multi-model rooms. Typing @ and a model name summons it, and replies stream in real time ([docs](https://docs.openwebui.com/features/channels.md)). Its "agents" are configured models rather than named agents with identity. Since v0.6.6 its licence forbids altering or removing the Open WebUI branding unless you have 50 or fewer users in 30 days, written permission from a substantive contributor, or an enterprise licence ([licence](https://docs.openwebui.com/license/)). That makes it a reference only.

**open-tag** (`fancyboi999/open-tag`) is the closest conceptual match: a Slack-style workspace where Claude Code, Codex and Copilot are teammates in channels, threads, DMs and shared tasks, Apache-2.0, TypeScript ([repo](https://github.com/fancyboi999/open-tag)). It was created in late June 2026 and has about 31 stars per a third-party index. Its frontend framework and commit activity were not confirmed. Do not confuse it with the unrelated CopilotKit/OpenTag, an MIT Slack/Teams bot ([repo](https://github.com/CopilotKit/OpenTag)). Two smaller projects, nexor-agora (MIT, from a search summary only) and stoops-cli (licence unstated), also put humans and Claude sessions in one room. Their UI quality and maintenance were not checked.

Treat them as leads to check against live demos.

## Component kits: shadcn primitives and assistant-ui fit best

For a no-backend static export with our own in-memory transport, the transport-agnostic MIT kits are the candidates. Stream's `stream-chat-react` is out: it needs an API key and the `stream-chat` client, and its LICENSE is a proprietary source-code agreement that bars operating a service or combining it with open-source components in ways that could subject it to open-source licences ([licence](https://raw.githubusercontent.com/GetStream/stream-chat-react/master/LICENSE), summarised by a fetch tool). ChatKitty and CometChat are hosted SaaS ([search summary](https://github.com/ChatKitty/chatkitty-react-component-library)). `@virtuoso.dev/message-list` is virtualized and unstyled, but its npm licence is "Commercial" ([npm](https://registry.npmjs.org/@virtuoso.dev/message-list/latest)).

None of these ships mentions, threads and presence together without a backend. Typing and presence indicators and threads must be hand-built whichever kit is chosen. Because the repo has no Tailwind today, any shadcn-registry component means either adding a Tailwind build step or rewriting its classes into our CSS. ## Mentions, status and pause are patterns to implement, not components to install

The notes found specifications and protocols, not drop-in widgets, for the control surfaces the redesign needs.

**Mention autocomplete.** Tiptap Mention supports multiple trigger characters and custom popup rendering, but `@tiptap/suggestion` only exposes onStart/onUpdate/onKeyDown/onExit, so keyboard handling and ARIA are the integrator's job ([Tiptap](https://tiptap.dev/docs/editor/extensions/nodes/mention.md), [registry](https://tessl.io/registry/tessl/npm-tiptap--suggestion)). The W3C combobox pattern is the spec: focus stays in the textbox, `aria-activedescendant` points at the highlighted option in a listbox, Down moves, Enter accepts and Escape closes ([APG](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-autocomplete-list/)). The notes infer that a small custom component, or a headless combobox, beats trusting the editor. Linear gives the model for agents in the list: agents can be @mentioned and delegated issues, carry a small badge, and a human stays shown as responsible ([Linear](https://linear.app/developers/agents.md)). The notes found nothing usable on Lexical, Slate, react-mentions or cmdk.

**Typing and agent status.** Zulip documents a copyable timing protocol: the client sends "start" every 10 s while typing, sends "stop" after a pause of at least 5 s, and the indicator expires after 15 s ([Zulip](https://zulip.readthedocs.io/en/latest/subsystems/typing-indicators.html)). Linear's guidelines ask agents to show immediate feedback on invocation, emit a thought activity within 10 s, and expose session states including `stale` ([Linear AIG](https://linear.app/developers/aig.md)). The inference is to render agent status as a state (queued, working, awaiting approval, stale) with an expiring heartbeat, so a crashed agent cannot show "working" forever.

**Tool-call rendering.** MindRoom's collapsible traces, the AI Elements Tool component and AG-UI's tool-call and state-delta events are the leads. AG-UI is an event protocol over SSE, and its event count varies by doc version (16 in CopilotKit docs, 24 in the Kotlin SDK docs) ([CopilotKit](https://docs.showcase.copilotkit.ai/agentic-protocols/ag-ui)). The idea of a human card and a machine payload generated from one structured message is an inference. No project was found with an explicit side-by-side human and raw-JSON view.

**Pause and circuit breaker.** No source documents a dedicated kill-switch UI. What exists is approval gating. LangGraph interrupts persist across refresh and can be resumed from another component ([LangChain](https://docs.langchain.com/oss/langchain/frontend/human-in-the-loop)). Cline and Roo Code key auto-approve by tool category with a master toggle ([Roo](https://docs.roocode.com/advanced-usage/auto-approving-actions)). Linear says agents must step back immediately when asked ([Linear AIG](https://linear.app/developers/aig.md)). The notes' proposal, which is inference, is a persisted workspace pause flag that agents check before each step, with a persistent banner. A "max depth reached" stop would become a pinned system message with Approve and Deny whose state lives server-side.

**Lists and threads.** TanStack Virtual documents a chat recipe with `anchorTo: 'end'` and `followOnAppend`, without column-reverse tricks ([docs](https://tanstack.com/virtual/latest/docs/chat)). Plain react-virtuoso sends chat use cases to its commercial message-list package. For a few thousand messages per room the notes suggest skipping virtualization at first. Thread and side-panel design had almost no evidence beyond Linear's model of an agent session attached to a thread.

## Recommendation, licence cautions and unverified gaps

**Base the Delegator redesign on two things.** First, shadcn's unstyled `@shadcn/react` message-scroller with our own markup and CSS variables. It is the only candidate that is headless, built for chat, and designed around streaming and anchored scrolling. Pair it with a hand-written mention combobox that follows the W3C pattern, using assistant-ui's trigger-popover and directive format as the model (MIT, but check it first for Tailwind and base-ui coupling). Second, treat open-tag and MindRoom as the behavioural spec: agents as teammates in channels and threads, tag-required routing in multi-human threads, approval cards, and cancel commands. Add Zulip's timing numbers and Linear's agent-state rules for presence. Fall back to Chatscope (MIT, SCSS, backend-free, older look) if the shadcn primitives prove too immature. That fallback is a judgement from dependency stacks, not from tested builds. Avoid depending on AI Elements given its November 2026 deprecation, and treat MUI X headless as an alpha reference.

**Licence cautions.** Treat Element and Compound, Signal, Nextcloud Talk and Stoat as look-and-feel references only, because AGPL would likely attach to a shipped static bundle. Do not vendor Open WebUI (branding clause), Dify (multi-tenant and logo conditions per [Dify docs](https://docs.dify.ai/policies/open-source)), LobeChat (the notes found only mirrors suggesting a commercial licence for derivative works) or Zed (GPL/AGPL in tree). Do not use Stream's kit or Virtuoso's message-list. Exclude `ee/` and `enterprise/` directories in Rocket.Chat and Chatwoot, honour Mattermost's trademark rule, and re-check each icon, font and token licence separately.

**What the notes did not verify.** The researchers say plainly that much was read at snippet level.

- The building-blocks researcher did about 11 searches with no deep page fetches. The AI-agent-UI researcher says most candidates were not verified against repo LICENSE files or source. Most licence claims there come from secondary sources.
- No library was tested with React 19, Next.js 15 or a static export. No source states Next.js 15 compatibility, and no bundle sizes were measured.
- No kit's UX was checked from screenshots or demos. Modernity rankings and the "dated" label on Chatscope come from dependency stacks.
- The shadcn chat components' licence, their Tailwind usage, and whether they can run unstyled in a Tailwind-free repo were not read from source. Whether assistant-ui's runtime models multi-party rooms is unverified. The shadcn changelog reports a mount-anchor bug.
- open-tag's frontend framework, activity and quality, and nexor-agora's and stoops-cli's maintenance and licences, are unconfirmed.
- Open WebUI Channels' tool-call cards, stop controls and per-agent identity were not confirmed. The v0.6.29 mention changelog came from a repost.
- LibreChat, LobeChat, Dify, Langflow, Chainlit, OpenHands and AutoGen Studio were not checked for tool-call rendering. Chainlit's, Roo Code's, CopilotKit's and AG-UI's licences were not confirmed. LibreChat's MIT licence and its ClickHouse ownership rest on secondary sources.
- The Mattermost "Apache for webapp" reading came from a model summary of the licence file and should be re-read against the raw text. Stream's licence terms also come from a fetch-tool summary.
- Slack, Discord and Matrix typing and presence design, thread and side-panel write-ups, any kill-switch or incident-banner UI, and the Lexical/Slate/react-mentions/cmdk options returned nothing usable.
- Tiptap's ARIA accessibility is unconfirmed: a 2021 grant to add it was cancelled with completion unknown.

## Conclusion

The research shows the useful reuse is at the seam between design and licence. The designs worth copying (Element, Zulip, Slack-style threads) are either AGPL or not React, and the permissive React code is mostly AI-chatbot oriented, so a room of several humans and several named agents has to be composed. The behaviour is already specified elsewhere: MindRoom for routing and approval, Zulip for timing, Linear for agent states and responsibility, and the W3C pattern for mentions. A cheap next step is a one-day spike. Render the Delegator room on the unstyled shadcn message-scroller in a static export, and check its Tailwind coupling and mount-anchor bug before committing.
